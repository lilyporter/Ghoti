Distance and acoustic support

Two views of the target, with different meanings. Neither is a pronunciation percentage.

Target phone / groupSymbolic feature distance · lower is closerAcoustic log margin · right favors target

Feature distance uses IPA categories. Group distance is the mean only when every target phone has a feature comparison; a gap makes it unavailable. Group acoustic margin is the weakest (minimum) phone margin. Syllable groups are supplied manually, not detected from audio.

Plots show distances 0–12 and margins −10 to +10 nats; marks beyond these ranges are clipped while numeric labels remain unclipped. An outlined circle is the synthetic control recording, not a clinical norm.

How this frontend connects to the engine
01 · RecognizeThe Python engine converts a recording into IPA phone tokens. This HTML file does not run Pasketti.
02 · CompareSupply a target and acceptable variants to analyze(). The engine aligns phones and looks up feature vectors.
03 · ReviewThis page renders the resulting JSON as sound pairs, candidate counts, and a feature map.

From the engine folder, create an analysis file and use “Open analysis JSON” above:

python -m pronouncedfish_engine recognize sample.wav > recognition.json
python -m pronouncedfish_engine analyze recognition.json --expected-phones ð ə ɹ æ b ɪ t s ɪ t s ɪ n ð ə s ʌ n > analysis.json
# Or produce recognition, analysis, and acoustic evidence in one forward pass:
python -m pronouncedfish_engine assess sample.wav --expected-phones ð ə ɹ æ b ɪ t s ɪ t s ɪ n ð ə s ʌ n > assessment.json

A connected application would call the Python engine through its application backend and pass the result to this view. No backend connection, microphone capture, model inference, or persistent session storage is included here. Files are read in this page; this demo makes no network requests.

Acoustic evidence compares full-sequence CTC probabilities under single-phone substitutions. It is not full GOP-SF, a correctness probability, an acoustic feature detector, or a clinical score. Unsupported multi-class target phones return unavailable. The “Synthetic sentence” example is an actual offline model run on a generated voice; the other six are illustrative phone inputs.

Targets and variants must be supplied by the application. Inventory membership on a substitution only reflects the caller’s supplied pairs; it does not establish clinical validation. Empty or unassessable recognition produces no inferred omissions. Unknown feature mappings and alignment gaps have no distance.
